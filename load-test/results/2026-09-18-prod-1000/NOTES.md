## 무엇이 잘못됐나 — 도구 결함 (서버 아님)
- k6 완료 iteration **886,835개** (정상이면 5,000개 안팎). 17:41부터 맥 임시 포트 고갈(`can't assign requested address`).
- 서버 지표(인스턴스 1대): `/signaling` 핸드셰이크 **401 = 203,452회**, 101 = 131,064회.
  메시지 처리: CREATE 29,004 / JOIN 102,377 / OFFER 28,004 / ICE 557,025 / PING 3,870 / END_SESSION 34.
- 원인: 스크립트가 VU당 액세스 토큰을 최초 1회만 발급해 90분 내내 재사용(재접속 계약상 의도된 설계).
  토큰 수명(1시간, 운영 값 확인 필요)이 지나면 새 세션의 소켓 핸드셰이크가 401 → 스크립트는 "연결 실패"로
  즉시 다음 세션 시도 → 초당 160회 헛도는 루프. 이전 운영 테스트(15~25분)에서는 드러나지 않던 결함.
- 서버는 무관: CPU 0.2%, 파일 디스크립터 37/524,288, 리퍼 종료 ~450, 힙 정상. 한 시간 동안 초당 160건의 401
  핸드셰이크를 받고도 이상 없음(부수 관찰일 뿐 용량 근거 아님).

## 결론
- **1,000세션 유지 여부는 이 실행으로 판정할 수 없다.** 발표는 "1대 500세션(1,000연결) 실측 기반 산정"으로 유지.
- 다음 실행 전 필수 수정(스크립트): ① 새 세션 시작 전 토큰 만료 2분 이내면 `/auth/refresh`로 갱신(레이트리밋 없음),
  재접속은 계약대로 같은 토큰 유지 ② 수립 전 연결 실패는 즉시 재시도 대신 5초 대기(포트 폭주 방지).
