# WebSocket 재연결 계약 (시그널링)

> 서버와 클라이언트(모바일)가 "끊겼을 때 어떻게 할지"에 대한 약속. 서버 #106·#111 릴리스부터 유효하며,
> 운영 실측(load-test/results/2026-09-01-111-after/)으로 검증됨. 이 문서의 변경은 릴리스 노트에서
> 모바일 required로 공지된다.

## 원칙

**시그널링 소켓의 종료 ≠ 세션 종료.** 배포·망 전환·장애 어떤 이유로 끊겨도 세션 상태는 서버(Redis, TTL 10분)에
살아 있고, WebRTC P2P 연결은 서버와 무관하게 유지된다. 클라이언트는 **P2P를 끊지 말고** 시그널링만 재접속한다.

## 1. 끊겼을 때 — close 코드별 행동

| 코드 | 의미 | 클라이언트 행동 |
|---|---|---|
| **1012** (SERVICE_RESTARTED) | 서버 배포·재시작. 곧 다른 인스턴스가 받는다 | **0~1초 무작위 대기 후 즉시 재접속.** 연속 1012가 2회를 넘으면 backoff로 전환 |
| **1008** (POLICY_VIOLATION) | 인증 실패 등 정책 위반 | 재접속 금지. 토큰 재발급 등 원인 해소 후 |
| 1000 / 1001 / 1006 / 그 외 | 정상 종료 / 서버 이탈 / 비정상(코드 없음) | 지수 backoff 재접속: `min(1s × 2^attempt + random(0~1s), 30s)`, 성공 시 attempt = 0 |
| (핸드셰이크가 **HTTP 503**) | 드레인 중 인스턴스에 착지 | backoff 후 재시도 — ALB가 다른 인스턴스로 보낸다 |

무작위 지연(jitter)의 이유: 배포 시 수백 소켓이 동시에 끊기므로, 동시 재접속(스탬피드)을 흩뜨린다.
서버도 끊는 시점을 3초에 분산하므로 이중으로 완화된다.

## 2. 재접속 — 상태 복원

1. **기존 토큰 재사용** — `/auth/guest`를 다시 호출하지 않는다 (같은 userId여야 자리 인계가 된다)
2. 같은 `sessionCode`로 `JOIN_SESSION` 전송
3. 서버가 자리를 인계(takeover)하고 **`SESSION_RESUMED`** 응답:
   ```json
   { "type": "SESSION_RESUMED", "sessionCode": "...", "currentDirectorUserId": 1, "status": "CONNECTED" }
   ```
   - `currentDirectorUserId`: 공백 중 역할 교체가 있었어도 이 값이 최종 상태
   - `status`: `WAITING`이면 공백 중 상대가 이탈한 것 — 대기 화면으로
4. 상대에게는 `PEER_RECONNECTED`가 간다. 배포로 끊긴 경우 `PEER_DISCONNECTED`는 **가지 않는다**
   (서버가 슬롯을 유지하므로) — `PEER_RECONNECTED`를 멱등하게 처리할 것

## 3. 놓친 것 복구 — replay가 아니라 스냅샷·재전송

공백(수백 ms~수 초) 동안 상대가 보낸 시그널링 메시지는 유실될 수 있다. 복구 규칙:

| 잃을 수 있는 것 | 복구 |
|---|---|
| SWAP_ROLE / 상대 이탈 | `SESSION_RESUMED`의 `currentDirectorUserId` / `status` 스냅샷 |
| SDP/ICE (수립 중이었다면) | **P2P 미수립 상태로 복귀하면 디렉터가 OFFER를 재발신**한다 |
| DEVICE_SPEC | `PEER_RECONNECTED`를 받으면 자신의 DEVICE_SPEC을 재전송한다 (권장) |

이벤트 replay는 하지 않는다 — 시그널링 상태는 작고 SDP/ICE는 재생성이 관례이므로 스냅샷이 더 단순·안전하다.

## 4. 배포 시 실제로 일어나는 일 (서버 동작, 참고)

```
ASG가 인스턴스 종료 결정 → 서버가 이를 감지(IMDS)하고 즉시:
  ① 새 핸드셰이크 503 거절 → ② 기존 소켓에 1012를 0~3초 분산 전송 → ③ 정리 후 종료
클라이언트: 1012 수신 → 0~1s 후 재접속 → ALB가 살아있는 인스턴스로 → SESSION_RESUMED
```

운영 검증 수치(50세션 롤링, 2026-09-01): 1012 수신률 100%, 복원 성공 150/150,
복원 시간 med 0.61s / p95 1.07s, 세션 사망 0. 배포 중에도 촬영(P2P)은 끊기지 않는다.

## 5. 유지 규칙 (기존, 재확인)

- 클라이언트는 25초 주기로 `{"type":"PING"}` 전송 (미전송 시 90초 후 서버가 소켓 정리)
- 재접속 가능 창 = 세션 TTL 10분 (PING이 연장)
