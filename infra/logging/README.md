# ALB 액세스 로그 (#138)

앱 로그에는 **무엇을 요청했는지**만 남고 **누가 보냈는지**는 남지 않는다.
ALB는 모든 요청이 지나가는 문이므로, 여기에 기록을 켜 두면 발신 IP와 사용자 에이전트를 확인할 수 있다.

## 켜게 된 계기

2026-09-29 12:16 KST `peakpic-alb-5xx-spike` 알람. 1분 안에 `POST /auth/callback` 24건과
멀티파트 요청 2건이 들어왔고, 서버에 없는 경로라 전부 500으로 응답했다(#137에서 404로 수정).
앱·랜딩·개발자 콘솔 어디에도 이 경로가 없어 외부 스캐너로 판단했지만, 발신자를 특정할 기록이 없었다.

| 암호화 | SSE-S3 (ALB 로그는 KMS 키를 지원하지 않는다) |
| 퍼블릭 액세스 | 전부 차단 |
| 버전 관리 | 비활성화 |

| 대상 | `peakpic-alb`의 액세스 로그만. 연결 로그·상태 검사 로그는 끔 |

CloudTrail 버킷과 분리했다. 감사 기록 버킷에 다른 서비스의 쓰기 권한을 열지 않기 위해서다.

### 버킷 정책

서울 리전의 ELB 계정(`600734575887`)에 지정 경로의 쓰기만 허용한다.

```json
{
  "Version": "2012-10-17",
  "Statement": [{
    "Effect": "Allow",
    "Principal": {"AWS": "arn:aws:iam::600734575887:root"},
    "Action": "s3:PutObject",
    "Resource": "arn:aws:s3:::peakpic-alb-logs-063562646825/alb/AWSLogs/063562646825/*"
  }]
}
```

ALB 속성에 입력하는 주소의 접두사(`alb`)가 정책의 경로와 다르면
`Access Denied for bucket` 오류로 저장되지 않는다.

## 조회

파일은 5분 단위로 아래 경로에 쌓인다. 요청이 없던 구간에는 파일이 생기지 않는다.

```
alb/AWSLogs/063562646825/elasticloadbalancing/ap-northeast-2/YYYY/MM/DD/
```

알람 시각(UTC)의 파일을 내려받아 경로나 응답 코드로 찾는다.

```bash
gunzip -c <파일>.log.gz | grep "auth/callback"
gunzip -c <파일>.log.gz | awk '$9 >= 500'
```

| 위치 | 내용 |
|---|---|
| 2번째 값 | 요청 시각 (UTC) |
| 4번째 값 | 발신 IP:포트 |
| 9번째 값 | 대상(앱)이 돌려준 상태 코드 |
| 첫 번째 따옴표 묶음 | 메서드·주소·프로토콜 |
| 두 번째 따옴표 묶음 | 사용자 에이전트 |

Referer는 기록되지 않는다.

### 판정 기준

| 로그의 모양 | 판정 |
|---|---|
| IP 하나에서 몇 초 간격으로 연속, 사용자 에이전트가 도구 이름 | 스캐너 |
| 사용자 에이전트가 우리 앱 또는 브라우저, 간격이 띄엄띄엄 | 클라이언트 쪽 경로 오류 |
